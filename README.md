# Music SQL Database

## Overview

This project is a **SQL-based music database** designed to store, organize, and query information about music tracks. The database contains information such as **artists, genres, track lengths, and other music-related attributes**.

A Python program provides the application logic used to interact with the database and execute queries, allowing users to retrieve and work with the stored music data.

## Project Components

### SQL Database

The SQL files contain the database structure, tables, relationships, and queries used to organize and retrieve music information.

The database includes populated data that can be queried based on different track attributes, such as:

* Artist
* Genre
* Track length
* Album and track information
* Other stored music metadata

### Python Program

The **`Music DB Program Edenburn.py`** file contains the Python application logic used to interact with the music database. It allows database queries to be executed through the program and processes the resulting information.

### SQL Assignments & Queries

Additional SQL files demonstrate database design and query functionality, including:

* **`MusicPlaylist.sql`** — Music playlist database and related SQL operations.
* **`multi-table-assign.sql`** — Queries involving multiple database tables and relationships.
* **`summary-assign.sql`** — Summary and aggregate queries performed against the database.

## Database Population

The project includes populated SQL data used to create and test the database. This provides a dataset that can be queried by the Python application and SQL statements.

## Objective

The primary objective of this project is to demonstrate practical experience with **relational databases, SQL queries, database relationships, and Python database integration**.

The project demonstrates how structured music data can be stored in a relational database and accessed programmatically through Python.

## Technologies

* **SQL** — Database structure, data population, and queries
* **Python** — Application logic and database interaction
* **Relational Database Concepts** — Tables, relationships, queries, and data organization
